Bonnes pratiques & Déploiement professionnel

Ce chapitre bonus couvre les aspects avancés pour passer d'un usage personnel à une architecture professionnelle de production.

Bonnes pratiques générales

📝 Nommage

  • Workflows : [Domaine] Action - Description
  • Ex: [Marketing] Lead Capture - Facebook to Brevo
  • Nœuds : nommer selon leur rôle, pas le type

🧩 Modularité

  • Découper les gros workflows en sous-workflows
  • Utiliser « Execute Workflow » pour la réutilisation
  • 1 workflow = 1 responsabilité

📋 Documentation

  • Sticky Notes sur le canvas
  • Description du workflow (champ description)
  • Versionner les exports JSON dans Git

Sécurité

⚠️ Règles de sécurité essentielles
  • Credentials : Toujours via le gestionnaire n8n, jamais en dur dans les nœuds
  • Webhooks : Ajouter une authentification (header secret, basic auth)
  • HTTPS : Obligatoire en production (reverse proxy Nginx/Caddy)
  • Variables d'environnement : Pour les secrets au niveau serveur
  • Accès : Limiter l'accès à l'interface admin (VPN, IP whitelist)
  • Mises à jour : Maintenir n8n à jour (CVE régulières)
# Variables d'environnement recommandées
N8N_BASIC_AUTH_ACTIVE=true
N8N_BASIC_AUTH_USER=admin
N8N_BASIC_AUTH_PASSWORD=mot-de-passe-fort
N8N_ENCRYPTION_KEY=cle-aleatoire-32-caracteres
WEBHOOK_URL=https://n8n.votredomaine.com/
N8N_SECURE_COOKIE=true

Gestion des erreurs

Chaque workflow professionnel doit gérer les erreurs :

Trigger
→
Action principale
→
Succès

↓ En cas d'erreur ↓

Error Trigger
→
Log erreur
→
Alerte Slack/Email
  • Error Trigger : Workflow séparé qui s'active sur toute erreur
  • Retry : Configurer les retries sur les nœuds HTTP (Settings → Retry On Fail)
  • Continue On Fail : Pour les branches non-critiques
  • Timeout : Définir des timeouts sur les appels API longs

Logs & Monitoring

# Activer les logs détaillés
N8N_LOG_LEVEL=info
N8N_LOG_OUTPUT=console,file

# Monitoring avec healthcheck
GET https://n8n.votredomaine.com/healthz
→ Retourne 200 si n8n fonctionne

# Alertes recommandées :
- Échecs consécutifs > 3 → Slack/PagerDuty
- Temps d'exécution > 5 min → Warning
- Espace disque < 20% → Alerte admin

Architecture de production recommandée

🌐 Internet → Caddy/Nginx (HTTPS, reverse proxy)
→
🐳 Docker : n8n (app) + PostgreSQL (DB) + Redis (queue)
→
💾 Volumes persistants + Backups automatiques

Déploiement VPS avec Docker

# docker-compose.prod.yml
version: '3.8'
services:
  postgres:
    image: postgres:15
    restart: always
    environment:
      POSTGRES_DB: n8n
      POSTGRES_USER: n8n
      POSTGRES_PASSWORD: ${DB_PASSWORD}
    volumes:
      - postgres_data:/var/lib/postgresql/data

  redis:
    image: redis:7-alpine
    restart: always

  n8n:
    image: n8nio/n8n
    restart: always
    ports:
      - "127.0.0.1:5678:5678"
    environment:
      - DB_TYPE=postgresdb
      - DB_POSTGRESDB_HOST=postgres
      - DB_POSTGRESDB_DATABASE=n8n
      - DB_POSTGRESDB_USER=n8n
      - DB_POSTGRESDB_PASSWORD=${DB_PASSWORD}
      - EXECUTIONS_MODE=queue
      - QUEUE_BULL_REDIS_HOST=redis
      - N8N_BASIC_AUTH_ACTIVE=true
      - N8N_HOST=${DOMAIN}
      - WEBHOOK_URL=https://${DOMAIN}/
    volumes:
      - n8n_data:/home/node/.n8n
    depends_on:
      - postgres
      - redis

volumes:
  postgres_data:
  n8n_data:

Alternative PM2 (sans Docker)

# ecosystem.config.js
module.exports = {
  apps: [{
    name: 'n8n',
    script: 'n8n',
    args: 'start',
    env: {
      N8N_PORT: 5678,
      N8N_BASIC_AUTH_ACTIVE: 'true',
      WEBHOOK_URL: 'https://n8n.mondomaine.com/'
    }
  }]
};

# Commandes PM2
pm2 start ecosystem.config.js
pm2 save
pm2 startup
