Module 4

Premier Workflow complet

Construisons ensemble un workflow API complet : recevoir des données via webhook, les transformer, et renvoyer une réponse.

Étape 1 — Webhook (Trigger)

Le nœud Webhook crée une URL qui écoute les requêtes HTTP entrantes.

  1. Ajoutez un nœud Webhook
  2. Méthode : POST
  3. Path : contact
  4. Response Mode : Using 'Respond to Webhook' Node

URL générée : http://localhost:5678/webhook/contact

Étape 2 — Set Node (Transformation)

Le nœud Set (Edit Fields) permet de créer ou modifier des champs.

// Champs à ajouter dans Set :
name  → {{ $json.body.name }}
email → {{ $json.body.email }}
date  → {{ $now.toISO() }}
source → "webhook-contact"

Les expressions {{ }} accèdent aux données des nœuds précédents.

Étape 3 — Function Node (Code JavaScript)

Le nœud Code (anciennement Function) exécute du JavaScript personnalisé.

// Validation de l'email
for (const item of $input.all()) {
  const email = item.json.email;
  const isValid = /^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(email);

  if (!isValid) {
    item.json.error = 'Email invalide';
    item.json.valid = false;
  } else {
    item.json.valid = true;
    item.json.message = `Merci ${item.json.name} !`;
  }
}
return $input.all();

Étape 4 — Respond to Webhook

Renvoie une réponse HTTP au client qui a appelé le webhook.

// Configuration Respond to Webhook :
Response Code: 200
Response Body: {
  "success": {{ $json.valid }},
  "message": "{{ $json.message || $json.error }}"
}

Exercice guidé complet

📝 Exercice — API de contact
  1. Créez le workflow avec les 4 nœuds ci-dessus
  2. Activez le workflow (toggle en haut à droite)
  3. Testez avec curl : 
    curl -X POST http://localhost:5678/webhook/contact \
  -H "Content-Type: application/json" \
  -d '{"name":"Alice","email":"alice@test.com"}'
  4. Vérifiez la réponse JSON
  5. Testez avec un email invalide : "email":"pas-un-email"
  6. Consultez l'exécution dans l'onglet Executions

Email valide :

{"success": true, "message": "Merci Alice !"}

Email invalide :

{"success": false, "message": "Email invalide"}

💡 Bonnes pratiques
  • Toujours activer le workflow pour que le webhook fonctionne
  • Utiliser « Respond to Webhook » pour contrôler la réponse HTTP
  • Tester avec curl ou Postman avant de connecter une vraie app
  • Séparer validation (Function) et formatage (Set) pour la lisibilité

📋 Résumé

  • Webhook = point d'entrée HTTP
  • Set = transformation simple sans code
  • Function/Code = logique JavaScript avancée
  • Respond = réponse HTTP au client
